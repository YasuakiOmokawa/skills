## 目的

技術選定または実現可能性の問いに、候補と評価軸の星取表を最小の実験で埋めて答え、成功基準を満たす最適な候補を選ぶ。

## 原理

- spike と意思決定表: 候補 (行) × 評価軸 (列) の星取表を実験前に作り、結論を左右するセルに絞った最小の局所実験で埋める。依頼が候補を絞っていても、構成の分かれ目から指定外も含めて候補を貪欲に列挙し、各選択肢が候補になるか否かの理由を脚注に記す。列は必須か選好かを示し、必須の列は閾値を列見出しに書く。`○` (観測した合格)・`△` (条件付き合格。条件と影響を添える)・`×` (観測した不合格) は閾値のある列だけに使い、選好の列は相対順位と実測値で埋める。測定単位と除外する費用は実験前に固定する。多義的な条件は解釈ごとに列を分け、依頼文言に忠実な解釈を必須の列として確定を判断主体に求める (全解釈で結論が変わらないなら待たず完了できる)。選好条件と優先順位が依頼に無ければ、表の設計時に確定を求める。依頼に無い測定入力は seed で固定して記録し、妥当性の確定を申し送る。測らない候補は理由を添えて「測らない」と記し、`×` にしない。
- 推測と観測の分離: 観測済みのセルだけに `○△×` を付け、調査・推定だけのセルは `未検証` とする。観測値と公開された上限から計算した値は式を記録して観測とする。依頼が利用可能と示していないデータや環境で代替した観測は、判断主体が受け入れるまで `未検証` とし、参考値として記録する。`未検証` のセルや候補には不足する証拠だけを述べ、参考値・推測・見込みは星取表に置く。同じ実験は状態が変わった根拠があるときだけ繰り返す。

## 契約

- 入力: 依頼の問いと条件、許可された作成範囲、結果の出力先ディレクトリ。出力先が未指定なら推測せず指定を求め、作成範囲や作業ディレクトリを出力先とみなさない。出力先が未確定の間は星取表と観測を回答本文に持ち、未確定のまま終えるなら `poc.md` の内容の全量を回答で返す。
- 出力: 出力先直下の案件ディレクトリ `<案件slug>` (slug は問いを表す kebab-case) の `poc.md`。同名の案件ディレクトリが既にあれば書き込まず別名か追記の指示を求める。見出し `## 問い`・`## 星取表`・`## 結論`・`## PR`・`## 申し送り` は後続が読む。実験の前に `## 問い` と `## 星取表` を書き、以後は節単位で更新し、未完了でも結果で仕上げて保存する。測定条件、試行別の観測値、未検証事項を含める。
- `## 結論`: PoC の完了可否、推奨候補 (該当が無ければ無し)、推奨の根拠となるセル、推奨が前提にする `△`・解釈・受け入れ済みの `未検証`、候補ごとの棄却理由、推奨が覆る条件。観測済みの必須条件が `×` の候補を棄却し、必須条件が全て観測済みの `○` か `△` の候補を優先順位の高い選好条件から順に比べ、最上位を暫定採用の推奨にする。推奨が指定外でも採用の確定は判断主体に求める。
- 検証コード: 完了・no-go・中断のいずれでも、人が書いた検証コードだけを元のブランチから切った `poc/<案件slug>` に commit・push し、元のブランチを base とする draft PR を作る。元のブランチと元の作業ツリーには残さない。リポジトリが無い、またはルートが変更を許された領域の外ならブランチも commit も作らない。remote や PR 作成手段が無いと読み取りで分かった操作は試行せず対象なしとする。起動が push と draft PR の承認を含むので、依頼が外部状態の変更を禁じない限り行う。
- `## PR`: draft PR の URL、作れなかったときはブランチ名と失敗内容、リポジトリが無いときは検証コードの所在。元の作業ツリーに残置したときはその事実と除去手順。
- `## 申し送り`: 新しいセッションが `poc.md` だけで前提を再構成できる自己完結した内容。判断主体の決定を待つ事項 (採用承認、選好条件の確定、未承認の測定) を承認待ちと明記する。

## 禁止

- 許可された局所対象の外への書き込み。生成物は許可された作成範囲の内側で除外を設定してから実験する。
- 上記の push と draft PR 以外の外部状態の変更は、変更先と内容が承認された場合だけ行う。

## 完了条件

- 推奨候補の全必須条件が観測済みの `○` か、判断主体が条件と影響を受け入れた `△` で、結論を覆し得る `未検証` (必須条件と、選定に使う選好条件のセル) が無いとき、または全候補が観測済みの必須条件で棄却されて no-go を判断できるとき、PoC は完了する。それ以外は完了とせず、不足する証拠、追加測定の条件、必要な決定を `## 申し送り` に書く。
- 新しいセッションが `poc.md` と `## PR` から検証コードにたどり着いて再利用できる。再読取などで確かめていない書き込みを成功と報告しない。
- 完了可否 (`## 結論`) と承認待ち (`## 申し送り`) は別々に書く。採用が承認され、残る問いがコードベースとの適合性だけのときに限り、プロトタイプへ進めると判断する。回答は `poc.md` のパス、星取表、結論、承認待ち、PR の URL または失敗、未検証事項、次に担う責務を返し、別 skill は暗黙に起動しない。
