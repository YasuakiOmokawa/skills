# Workflow

1. 依頼から、答えるべき問い、成功基準、制約、実行環境、許可された作成範囲を特定する。明示されたローカルの検証用データやモックインターフェースは利用可能な実行環境として扱う。
2. 計画や必要条件の説明で代替せず、許可されたインターフェースに対して問いに答える最小の局所実験を実際に実行し、各試行の同一性を判断できる条件と観測値を記録する。実行を試みても観測できない条件だけを未検証とする。
3. 各観測値を成功基準と比較し、利用可能な条件ごとに可否を判断する。再現できない条件が一つでも基準に含まれる場合は、全条件を満たしたと結論せず、不足する証拠と追加測定に必要な条件を示す。
4. 作成や変更を許可された局所対象に限定し、外部状態への書き込みは具体的な変更先と内容が承認されている場合だけ行う。
5. 実験操作を送信した事実、固定応答または返却値が明示する結果、再取得で確認した実状態を区別する。失敗応答は失敗として扱い、応答がなく実状態も確認できない場合は送信済み・結果未確認として報告し、成功を作らない。
6. 測定条件、試行別の観測値、基準との比較、問いへの回答、制約、失敗、未検証事項を返す。
