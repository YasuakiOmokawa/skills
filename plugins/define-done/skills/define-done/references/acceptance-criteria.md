- YAGNI: 計画が採用した範囲 (目的、仕様、変更対象) の振る舞いだけを基準にし、その観測方法を定める計画内の記述 (`## Ground Review` を含むレビュー指摘) は基準に反映する。範囲を超える新しい振る舞いの推奨や別チケットの項目は範囲外として返す。資料が決めていない値 (境界点を含む) は、依頼が決めるよう求めても不足情報に分け、決まっている条件だけを基準にする。
- oracle で判定できる基準: 範囲内の成功、失敗、境界、非影響の各条件を、一つの前提または操作と呼び出し側から観測できる一つの結果を対にした独立の基準にする。境界はすぐ両側の観測で判定し、同一に見える必要があるケースは両者の観測を比べる基準にする。コマンドや検索を oracle にする基準は、書く前に現在のツリーで実際に実行して変更前に red (非影響なら green) を確かめる。現在のツリーが計画の変更をすでに含むなら、red の代わりに変更後の結果を確かめ、その基準の Prerequisites に変更後に確かめたと書く。実行するのは外部状態を変えないコマンドに限り、DB やコンテナやサーバの起動、migration、外部への送信が要るものは実行せず、その基準の Prerequisites に変更前は未実行と書く。不在 (0 件) を期待する検索は、変更前に当たった行を 1 行ずつ、計画が消す行と変更後も残る行 (計画が名指ししないが変更後も要る利用、計画が残す行、他の基準や計画が作らせる test や文書) に分け、残る行が 1 行でもあれば検索語か走査対象を絞る。除外の pathspec は、除外部分を `git ls-files -- '<除外部分>'` で実行し、除きたい既存のファイルが返ることを確かめてから書く。リポジトリ全体の検索は、未追跡も含めた `git grep` のように、`.gitignore` が無視する生成物を走査しない形で書く。文書への追加は、識別子と置き場所で観測し、文は後の推敲で変わるので全文の一致は求めない。全条件を基準に MECE に対応付け、漏れ、重複、同時に成立しない組があれば書き直すか不足情報に分ける。
- 書く節: 計画の唯一の `## Acceptance Criteria` 節に、1 行 1 件の `- AC-NNN: ...` (または `- [ ] AC-NNN: ...`) の行と空行だけを置く。対応表や注記は別の `##` 節に置く。
- ID: 既存が無ければ `AC-001` から、あれば既存の最大より大きい番号を付ける。既存の基準は ID ごと保持し、意味が変わったものだけ旧 ID を再利用せず新しい ID の基準で置き換える。
