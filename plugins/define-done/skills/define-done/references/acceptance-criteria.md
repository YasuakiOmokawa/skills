- YAGNI: 要求が求める範囲の振る舞いだけを基準にし、その観測方法を定める計画内の記述 (`## Ground Review` を含むレビュー指摘) は、書いてよい名前の範囲で基準に反映する。範囲を超える新しい振る舞いの推奨や別チケットの項目は範囲外として返す。資料が決めていない値 (境界点を含む) は、依頼が決めるよう求めても不足情報に分け、決まっている条件だけを基準にする。要求の条件を満たさない入力 (条件の外側) は、決めていない値に当たらない。
- 基準は 2 種類だけ: 実装はこの 2 種類を満たす範囲で自由に選べるものとし、基準は実装の選び方を縛らない。
  - `[振る舞い]`: 一つの前提または操作と、外の呼び出し側から観測できる一つの結果の対。外とはリポジトリのコードの外にいる主体 (利用者、他のサービス、CI、運用者、文書の読み手) で、仕様の節が名指しした interface と、既存の試験が固定している既存の interface も外の境界に含める。リポジトリの中で export された関数は、ここに挙げたもの以外は外に含めない。境界は interface であり、動いている環境でなくてよい (HTTP の handler をプロセス内で呼ぶ、など)。実行時に起きてはならないこと (送らない、書き換えない) も、失敗か非影響の `[振る舞い]` にする。
  - `[禁止]`: コードに静的にあってはならないもの (秘密の混入、値の写し、禁じられた依存や直接の利用、旧名の残存) で、静的な検査か外部状態に触れない単体試験で検出できるもの。e2e や DB が要る試験でしか検出できないものは `[振る舞い]` にする。
  - どちらにも当たらないもの (計画が作る関数やファイルの名前、内部の呼び出し関係や包み方、実装の手順) は基準にしない。振る舞いの代わりに置かれた禁止 (「このファイルを変えない」など) は、守りたい振る舞いが変わらない非影響の `[振る舞い]` に書き直す。生成物 (bundle、build の出力) の中身も、要求が中身そのものを禁じるとき (秘密を含めない、など) だけ基準にし、振る舞い (route が応答しない、など) を確かめる代わりに使わない。
- 出典: 各基準は出典を持ち、出典にできるのは `## Requirements` の要求 (`R-n`) と、変更前の repo に既にある試験・guard (製品コードの中で入力を拒む検査を含む)・不変条件を述べる文書のパス (既存の保証) だけである。計画の決定 (選んだ手順・値・仕組み、`D` と数字の ID)、作るもの、変更対象、順序の節は出典にできず、決定だけが支える基準は作らない。
  - 既存コードの振る舞いと禁止は、要求か既存の保証が支え、かつ `## Ground Review` の pre-mortem が変更で壊れうると挙げたものだけを基準にする。支えの無い今の振る舞いは基準にせず、今の実装を固めない。
  - 要求が入力の受け付ける範囲を広げるか変えるとき、要求の条件を満たさない入力が変更前に受けていた扱い (拒否、例外) を保つことを、要求とその入力の検査を出典にした非影響の `[振る舞い]` にする。要求が触れていない入力は変えない。
  - 要求が書いた肯定の構造 (〜を使う、〜で包む、〜に置く) は、`[禁止]` に直して基準にする (「`readSession` を使う」は「`readSession` 以外が `getCookie` を直接使わない」)。直せないものは、判断の正本が決めて理由を書いたものなら実装の制約として範囲外に返し、それ以外は既定と行き先を添えて未決の判断にする。
  - 振る舞いを変えない改修の目的は `[禁止]` で書く (改名なら旧名が残らない)。書けなければ不足情報にする。
- 書いてよい名前: 基準と oracle に書く名前は、外の境界の名前、仕様の節が名指しした名前、判断の正本が名指しした外の境界の名前、既存の試験の seam の名前だけにする。計画の実装案 (決定、作るもの、変更対象、順序などの節) が挙げる新しい関数、型、ファイルの名前は書かない。判断の正本にあっても内部の関数名は書かない。文書の置き場所は読み手との境界として書いてよい。`[禁止]` が禁じる対象として名指しする名前 (改名でなくす旧名、直接使わせない依存) は書いてよい。
- oracle で判定できる基準: 範囲内の成功、失敗、境界、非影響の各条件を、独立の基準にする。境界はすぐ両側の観測で判定し、同一に見える必要があるケースは両者の観測を比べる基準にする。
  - 書く前に試す: コマンドや検索を oracle にする基準は、書く前に現在のツリーで実際に実行して変更前に red (非影響なら green) を確かめる。`[禁止]` は、禁じたものを探す pattern を走査範囲に、未追跡のファイルも含めた `git grep -n -E` で当て、変更前に当たる行を確かめる。現在のツリーが計画の変更をすでに含むなら、red の代わりに変更後の結果を確かめ、回答に変更後に確かめたと書く。実行するのは外部状態を変えないコマンドに限り、DB やコンテナやサーバの起動、migration、外部への送信が要るものは実行せず、回答に変更前は未実行と書く。
  - 禁止と不在の範囲: 禁止と不在 (0 件) を期待する検索は、変更前に当たった行を 1 行ずつ、計画が消す行と変更後も残る行 (計画が名指ししないが変更後も要る利用、計画が残す行、他の要求が残すと定める文書や作らせる試験) に分け、残る行が 1 行でもあれば、残る行に当たらないよう禁じる対象 (pattern) を絞るか、走査範囲を正の pathspec で絞る。除外の pathspec (`:!`、`:^`、`:(exclude)`) は書かない。リポジトリ全体の検索は未追跡も含めた `git grep` のように、`.gitignore` が無視する生成物を走査しない形で書く。
  - 文書の基準は、話題と置き場所 (識別子、見出し、ファイル) だけで観測する。計画の決定 (選んだ手順、値、仕組み) を文書の中身として基準に写さない。文は後の推敲で変わるので全文の一致は求めない。
  - 全条件を基準に MECE に対応付け、漏れ、重複、同時に成立しない組があれば書き直すか不足情報に分ける。
- 書く節: 計画の唯一の `## Acceptance Criteria` 節に、1 行 1 件の `- AC-NNN: [振る舞い] <本文> (出典: <出典>[, <出典>])` か `- AC-NNN: [禁止] <本文> (出典: <出典>)` (または `- [ ] AC-NNN: ...` の形) の行と空行だけを置く。出典は `R-n` か既存の保証のパスを `, ` で連結する。`[禁止]` の後にはあってはならないものを「〜を書かない」「〜を使わない」の形で書く。対応表や注記は別の `##` 節に置く。
- ID: 既存が無ければ `AC-001` から、あれば既存の最大より大きい番号を付ける。既存の基準は ID ごと保持し、意味が変わったものだけ旧 ID を再利用せず新しい ID の基準で置き換える。種類の印や出典を足すだけなら意味の変更に数えない。実装の名前を外して書き直した結果、観測するものが変わるなら意味の変更に数える。
