## 目的

リポジトリが決めた検査項目を PR の差分に漏れなく当て、CI が照合できる検査結果ブロックにする。

## 原理

- 項目は表とパスが決める: 検査する項目は、検査項目表の行のうち、対象の glob が変更ファイルのどれかに一致する行のすべてとする。項目は表の行だけから取り、一致した行はすべて検査する。
- 判定は根拠が決める: `OK` は、項目が成り立つことを `path:line` か実行したコマンドの出力で示せるときだけ付ける。成り立たない箇所を示せるなら `NG`、どちらも示せないなら `判断不能` とし、人が確かめる方法を根拠に書く。項目が問う変更が差分に無いときは、その観測を根拠にして `OK` とする。
- 結果は commit に結び付ける: 検査の対象は HEAD の commit とする。未 commit の変更があれば、検査結果ブロックを作らずに報告する。

## 契約

- 入力: 検査項目表と base。表は依頼が示したファイル、無ければ `.github/pr-checks.md` を読む。列は `ID`、`対象` (repo root からの glob。`,` 区切りで複数書け、`**` は全 PR)、`項目`。base は依頼、PR、リモートの既定ブランチの順で決め、変更ファイルは base との merge-base から HEAD までとする。表が無ければ検査せず、この列の表を求める。
- 出力 (CI が読む検査結果ブロック)。行は検査項目表の順に並べ、根拠は 1 行で書く。

```markdown
<!-- check-pr:start -->
検査した commit: `<HEAD の 40 桁の SHA>`

| ID | 判定 | 根拠 |
|---|---|---|
| <ID> | <OK / NG / 判断不能> | <根拠> |
<!-- check-pr:end -->
```

- 回答: ブロック、`NG` と `判断不能` の項目、書き込みの有無。
- 書き込み: 依頼が書き込み先 (PR 本文かファイル) を承認したときだけ、マーカーの間を置き換える。マーカーが無ければ末尾に足す。

## 禁止

- 製品コード、テスト、検査項目表を変更しない。`NG` は直さずに返す。
- マーカーの外の本文を書き換えない。

## 完了条件

選んだ行のすべてがブロックに 1 行ずつあり、ブロックの SHA が HEAD と一致することを確かめたとき完了する。書き込んだときは、書き込み先を読み直してブロックが一致することを確かめてから報告する。
