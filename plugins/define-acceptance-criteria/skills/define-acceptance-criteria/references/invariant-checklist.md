# 不変条件パターンチェックリスト

不変条件 AC の `[不変条件: <パターン>]` で使うパターン名。該当するものを以下から選ぶ。

不変条件は「**仕様書に書かれていなくても壊れてはいけない関係**」であり、AC の他 3 カテゴリとは導出元が違う。正常系 / 異常系 / エッジケースが「変更が何をするか」から導出されるのに対し、不変条件は「**ドメインが何を保証しているか**」から導出される。したがって観点軸 (controlled label) には紐づかず、必須セル数にもカウントしない。

## パターン

```
保存   → 集計値と明細の合計が一致する (同一時点の 2 経路が同じ値を出す)
連続   → 前期末の値と翌期期首の値が一致する / 前レコードの終端と次の始端が接続する
可逆   → 取り消し後に元の状態へ戻る / rollback 後に差分ゼロ
凍結   → 確定済みの過去データが後続操作で変化しない
一意   → 同一キーで二重に作られない / 二重送信で件数が増えない
同期   → 二重書き込み先の双方が同じ状態になる (片方失敗時は両方とも未反映)
冪等   → 同じ入力で N 回実行しても結果が 1 回実行時と同じ
```

## 適用トリガー (観測可能な述語)

Step 1 で確定した変更ファイル一覧・プラン本文に対し、次のいずれかが観測できるとき **不変条件カテゴリは必須**。いずれも観測できないときは 0 件でよく、`### 検討観点` に見送り理由を 1 文書く。

| トリガー | 観測方法 | 典型パターン |
|---|---|---|
| 期間・世代をまたぐデータを読み書きする | 会計期間 / 年度 / 締め / 繰越 / スナップショット / 履歴 / `*_at` による期間絞り込みがコードまたはプラン本文に現れる | 連続・凍結 |
| 集計値を保持または再計算する | 合計 / 残高 / 件数 / サマリーテーブル / カウンタキャッシュ | 保存 |
| 状態遷移を持つ | status / state / enum の遷移、取り消し・差し戻し・再実行の操作 | 可逆・凍結 |
| 書き込み先が 2 つ以上ある | 外部サービス連動 (gRPC / REST 呼び出し + 自 DB 書き込み)、dual write、非同期ジョブ経由の反映 | 同期 |
| 再実行されうる | batch / cron / webhook / retry / at-least-once 配信 | 冪等・一意 |

**リスク領域 (auth / billing / payment / DB migration) は tier 判定と同様、トリガー該当有無によらず必ず 1 件以上書く。**

## 書式ルール

不変条件行は **`- [ ] [不変条件: <パターン>]: <保たれるべき関係> (検証: <観測方法>)`** の形式で書く。

- `<保たれるべき関係>` は **等式または順序関係**として書く。「〜が正しく保たれる」は禁止 (何と何を比べるかが消えるため検証不能)
- `(検証: ...)` には**実装に依存しない観測方法**を書く。実装のメソッドを呼んで比べるのは実装追認になるので、DB 値・API レスポンス・画面表示など外から観測できるものを選ぶ。**実装非依存であることと観測点が実在することは別要件**で、両方が要る — 選んだ観測点 (画面の合計欄・特定の API フィールド等) が plan 本文またはコードで確認できない場合は `(検証: ... [観測点未確認])` と付す (「実装時に観測点を作る必要があるかもしれない」ことを下流に渡すため)

例:
```markdown
- [ ] [不変条件: 連続]: 期 N の期末簿価 == 期 N+1 の期首簿価 (検証: 両期の一覧 API を叩き当該資産の値を突合)
- [ ] [不変条件: 凍結]: 除売却した期の帳簿値が、翌期プレビュー実行後・年度締め後のいずれでも変化しない (検証: 締め前後で当該期の一覧を2回取得し diff がゼロ)
- [ ] [不変条件: 保存]: 明細の金額合計 == サマリーテーブルの合計値 (検証: `SELECT SUM(amount)` と summary レコードを比較)
- [ ] [不変条件: 同期]: 登録失敗時に外部ファイル保管サービス側のファイル実体と自 DB レコードのどちらも残らない (検証: 意図的に DB 書き込みを失敗させ、外部サービスの一覧 API に孤児が無いことを確認)
- [ ] [不変条件: 冪等]: 同一 webhook を 3 回受信しても作成レコードは 1 件 (検証: 同一 payload を 3 回 POST し件数を確認)
```

## 他カテゴリとの切り分け

| 迷うケース | 正しい置き場 | 理由 |
|---|---|---|
| 「二重送信で 400 を返す」 | 異常系 | 変更が返す**エラー応答の仕様**。トリガーへの応答であって保たれる関係ではない |
| 「二重送信してもレコードは 1 件」 | 不変条件 (一意) | 応答に関わらず**状態が保つ関係**。実装が 200 を返しても 400 を返しても成り立つ必要がある |
| 「境界値: 月末で正しく計算される」 | エッジケース | 特定入力に対する**期待出力**。1 点の検証 |
| 「どの月末でも前月末残高と当月首残高が一致する」 | 不変条件 (連続) | 入力によらず**常に成り立つ関係** |
| 「既存の一覧画面が変更前と同じ挙動」 | 非影響確認 | 変更**していない**箇所の回帰。不変条件は変更した箇所を含めて成り立つ関係 |

判定に迷ったら「**この AC は、期待値を仕様書から引かずに書けるか**」で決める。書けるなら不変条件、仕様書 (DD / PRD / 正本) が要るなら他カテゴリ。

**期待値と観測対象の同定は別物**。関係そのもの (何と何が等しいか) は仕様書なしで書けるが、比較する 2 点がどこにあるか (「翌期プレビューモードが指すのは翌期期首か期末か」等) の同定に未確定仕様が要ることがある。この場合も**不変条件のまま置いてよく**、行末に `(仕様確定要)` を付す — 関係自体は仕様が確定しても変わらないため、カテゴリを移すと確定待ちのあいだ関係が失われる。

## 件数

tier ごとの件数は SKILL.md の Quantitative scaffolding 表 (SSOT) を参照。**表の値は上限**で、該当トリガーから導ける関係がそれより少なければ少ないまま書く (トリガー 1 本しか該当しないのに上限 3 件に届かせようとして関係を発明しない)。トリガー非該当なら 0 件 + 見送り理由 1 文。

なお **1 トリガーから複数パターンが出ることはある** (「期間・世代をまたぐ」→ 連続と凍結の両方など)。トリガー本数と件数は 1 対 1 ではない。
