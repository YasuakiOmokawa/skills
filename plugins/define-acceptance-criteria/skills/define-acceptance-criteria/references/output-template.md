# 分析ファイル出力テンプレート

`/mece-plan-review` との contract のため**変更禁止**。分析ファイルパスは `<plan>.md` → `<plan>.analysis.md` (拡張子前に `.analysis` 挿入)。既存の `### Tier`、`## 受け入れ条件`、`## 技術リスク` は置換し、各1組だけ保持する。MECE後は既定で置換せず、`--reset-mece` 指定時だけ旧 MECE 追加・`## MECE分析結果`・プラン側 `- MECE判定:` を削除する。

SKILL.md が規定する `### Tier` 行は `## 受け入れ条件` より前に置く前置き節で、下の contract の parse 対象外 (見出しレベルは `###` のまま)。

```markdown
## 受け入れ条件

### 検討観点 (controlled vocabulary)
- 機械抽出変更種別: [api_change, db_change, ...] (Step 1.5 でマッピング結果)
- [controlled label 1]: [1文で理由を書く]
- [controlled label 2]: [1文で理由を書く]
- [controlled label 3]: [1文で理由を書く]
- 副作用軸の追加 (該当時のみ): [label] (理由: ...)  ← Step 2「主種別 + 副作用軸 1」
- 主軸採用 (該当時のみ): <label> (理由: ...)  ← Step 2「複数主種別 + プラン文脈軸の主軸採用」
- observability 追加 (該当時のみ): observability (理由: ...) ← Step 2「observability 軸の特例」
- 不変条件トリガー: [該当したトリガー名] → [採用パターン] (理由: ...) / 非該当の場合は「不変条件 見送り: [理由 1 文]」

### 正常系
- [ ] [controlled label]: [具体的な入力値 → 期待する出力値]
- [ ] ...

### 異常系
- [ ] [controlled label]: [条件] → [エラーメッセージ or HTTPステータス]
- [ ] ...

### エッジケース
- [ ] [controlled label] [境界値: カテゴリ名]: [条件]
- [ ] ...

### 不変条件
- [ ] [不変条件: パターン名]: [保たれるべき関係を等式/順序関係で] (検証: [実装に依存しない観測方法])
- [ ] ...

トリガー非該当で 0 件の場合はこの見出しを残したまま「トリガー非該当のため 0 件 ([理由])」と 1 行書く (見出しごと削除しない)

### 非影響確認
- [ ] [既存機能A]が変更前と同じ挙動であること
- [ ] [既存機能B]が変更前と同じ挙動であること

省略する場合は理由を 1 文で明記 (例: 「新規ファイル追加のみで既存ファイルへの変更ゼロのため非影響確認省略」)

## 技術リスク

### リスク1: [タイトル]
- **何がわからないか**: [不明な対象。例: dispatch側のエンドポイントが実装済みか不明。]
- **最悪何が起きるか**: [誰に+何が。例: 全ユーザーがログイン後に404になる。]
- **どうやって検証するか**: [例: `bundle exec rails runner "p UriService.generate(:sign)"` で確認]

### リスク2: [タイトル]
- **何がわからないか**: [不明な対象]
- **最悪何が起きるか**: [誰に何が起きるか]
- **どうやって検証するか**: [コマンド or 手順]

### リスク3: [タイトル]
- **何がわからないか**: [不明な対象]
- **最悪何が起きるか**: [誰に何が起きるか]
- **どうやって検証するか**: [コマンド or 手順]
```

## カテゴリ見出しの形式

- 全カテゴリ `###` 見出しで、見出し文字列はこの 5 つと完全一致 (`### 正常系` / `### 異常系` / `### エッジケース` / `### 不変条件` / `### 非影響確認`)。`### エッジケース (境界値チェックリストより)` のような補足を見出しに足すと `/mece-plan-review` 側で `カテゴリ:不明` に劣化するため、補足は見出しの下の行に書く
- AC 行は `- [ ]` チェックボックス必須 (正常系 / 異常系 / エッジケースは controlled label 行頭、不変条件は `[不変条件: <パターン>]` 行頭)
- カテゴリ見出しと AC 行のフォーマットは下流の `/mece-plan-review` AC enumerate contract が依存するため**絶対に変えない**
