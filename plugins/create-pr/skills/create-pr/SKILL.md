---
name: create-pr
description: 現在のブランチに対応するPRを作成または更新する。PRを開く、内容を改める、明示的にレビュー可能な状態にすることを求められたときに使う。
---

## 手順

1. 利用可能な文脈から現在のリポジトリとブランチを特定し、そのブランチに対応する PR を探す。作成時は、base ブランチ、タイトル、本文に必要な情報も特定する。
2. 新しい PR の作成または push の前に、worktree と base に対する未公開履歴を調べ、その状態で分岐する。未 commit の変更がある、または未公開履歴が目的を混在させているなら、PR は作らず、保留の理由 (この PR に含める変更の範囲は、branch 名から推測せず依頼者が決める) と、commit の作成・分割・並べ替えを担う先行作業の `create-commits` を返して終える。分岐は状態で決まり、依頼が commit や push を許していても変わらず、許可に従うのは、どちらでもない場合の push 以降である。
3. `create-commits` が作るようなレビュー可能な commit 境界を必須とする。すなわち、未 commit の変更が無く、各 commit がレビュー可能な一つの目的をそのテストや fixture とともに持ち、レビュアーが読むべき順に並んでいること。push または作成の前に、commit の順序と各 commit の diff をこの境界に照らして確認する。
4. 公開済みまたは共有済みの履歴は決して書き換えず、明示的な承認なしに force-push を決して行わない。作成に必要な情報や承認が欠けているか曖昧な場合、またはその履歴が書き換えなしには手順 3 の境界を満たせない場合も作成を保留し、各ブロッカーと、書き換えを伴わない安全な進め方を示す。
5. PR 本文は、呼び出し側が書式を渡していればそれに従い、無ければ PR の目的を述べる短い一文だけにし、それ以上は書かない。書式が渡されず、リポジトリに `.github/PULL_REQUEST_TEMPLATE.md` がある場合は、その一文をテンプレートの構造の下に置き、残りの節を埋めるために膨らませない。設計判断、背景、代替案、読む順序は、レビュアーまたはユーザーがその説明を求めた後に限って、求められた詳細を既存の本文に追記する形で加える。
6. 手順 2〜4 の保留に当たらないとき、説明で止まらずに、承認された作成または更新を実行する。ユーザーが明示的にレビュー可能な状態を求めない限り、新しい PR は draft として作成し、既存の状態は、その変更が明示的に求められない限り保つ。更新は、現在のブランチの PR と求められたフィールドに限定し、他のすべての PR、merge 状態、close 状態、ブランチは変えない。
7. `~/.claude/skills-config/release-labels.md` を読み、そこで定義されたグループごとに label を一つずつ選ぶ。生産性グループは変更の性質から、AI 貢献グループはセッションが実際に担った執筆の割合から、リリースレベルグループは設定されたコア機能への影響から選び、そのコア機能の一覧が空なら対象リポジトリの CLAUDE.md または README の冒頭から推定する。あわせて、そこで指定された milestone を選ぶ。
8. 対象リポジトリに存在することを確認した label と milestone だけを付ける。設定ファイル、グループ、該当する label、または milestone が無い場合は、その項目を飛ばして PR の操作を続け、飛ばしたことを理由とともに記録する。作成時は選んだ項目をすべて設定し、更新時は未設定の label と未設定の milestone だけを埋める。
9. 各 PR 操作は、その操作と同じ呼び出しの末尾で `gh pr view` などにより状態を出力し、base ブランチ、タイトル、影響を受けた内容、最終的な draft またはレビュー可能な状態を、返却値または出力した状態だけから確認し、確認だけの turn は作らない。送信したことは確認した結果と分けて記録し、応答が無いことから成功を推測せず、部分的な結果と権限エラーを記録して、裏付けの無い変更を主張しない。観測した PR 番号は、返された正確な URL と対にし、欠けている値を組み立て直さない。

## 完了

PR の操作を確認し終えたとき、または保留の理由と進め方 (先行作業、もしくは各ブロッカーと書き換えを伴わない安全な進め方) を返したときに完了する。確認した commit の順序と各 commit の目的、送信した操作、裏付けのある最終状態 (PR 番号と URL の対を含む)、適用した変更 (label と milestone を含む)、飛ばした項目の理由、理由付きの失敗、未解決の結果を報告する。
