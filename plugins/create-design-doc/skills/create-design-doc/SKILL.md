## 手順

1. プロトタイプ追記済みのPoC結果ファイル（`poc.md`）のパスが渡されたら読み、`## 問い`、`## 星取表`、`## 結論`、`## PR`、`## 申し送り`、`## Prototype` を根拠として扱う。指定された文書が無くこのファイルが渡されている場合は、同じディレクトリの `design-doc.md` を指定文書として扱う。
2. テンプレートが未指定なら `~/.claude/skills-config/create-design-doc/dd_template.md` と `~/.claude/skills-config/create-design-doc/dd_reference.md` を読む。存在しなければ承認済み根拠だけで続行してその縮退を報告し、手順11が列挙する観点を節構成とする。`dd_reference.md` は見出しの一覧を取ってから、書く節に必要な範囲だけ読む。
3. テンプレートの有無にかかわらず節見出しは省略せず保持する。根拠から承認済み計画の対象に該当しないと分かる節（または節内の項目）は、手順11の観点を除き、未解決判断にせず「該当なし」と理由を1行で書く。根拠が無いだけで該当するかどうかが分からない節は、不存在を推測せず、1行で対応する未解決判断を参照する。
4. 観測済みの事実、承認済みの判断、未承認の提案または仮定、未解決判断を区別する。
5. 採らない配置や責務から、その機能、データ、保持、移行自体が存在しないとは推論せず、明示的な根拠がない適用可能項目は未解決判断とし、根拠に一切の言及がない項目は関連するものをまとめて一件としてよい。
6. 未解決判断には実装を止めるか、必要な証拠または決定、判断主体を示し、判断主体が根拠から同定できない場合は未同定と記してその同定を必要な決定に含め、実装を止める範囲と止めない範囲を、コード実装と本番展開を分けて対で記し、実装を止めるものを先頭に個別記載する。実装を止めるとは承認済み計画の中核成果物に着手できないことを指し、承認済み計画の文面が未決の値で構造を決めると明記している成果物（テーブル定義やスキーマを含む）は、その成果物以外の部分が着手できても中核成果物の一部として止める側に分類し、移行（既存データの移し替えなど）、展開、運用だけが止まる項目は止めない側に分類する。
7. 観測済みの根拠どうしが同じ規範的記述について異なる配置や値を示す場合は、一方を採用せず衝突を明示した未解決判断として立て、両観測が共通して満たす性質と決着に必要な証拠を分けて記す。必要成果物が排他的に変わる差は実装を止める側、併存可能な差は止めない側の未解決判断とする。
8. 採らない代替案が根拠に存在しない場合は創作せず、比較根拠が存在しない事実を明記して、根拠から実際に導ける不採用判断だけを記す。
9. 承認済みと扱うのは、承認者が人間として明示されている判断と、判断主体である依頼者本人がこの依頼の中で値や方式を示して決めた判断だけとし、後者では承認者の氏名の有無を論点にしない。依頼者自身が未合意と述べた案と前工程の完了判定は承認と書き分け、設計承認を代行しない。
10. 依頼が前提として与えた承認済み計画は、承認者が未記載でも前提として採用する。承認者の同定は設計承認と実装可否の判定でだけ要求する。
11. 主要フロー、失敗時の扱い、確認方法、データ、保持、移行、展開、運用を含むDesign Doc内の各規範的記述を、承認済み計画、取得できた根拠、承認済み判断、または未解決判断のいずれかへ対応付ける。これらの観点は常に該当するものとして扱う。「該当なし」と理由を書いた節は、根拠への対応付けの一つとして数える。
12. 実装者が元のPoC結果ファイルや会話履歴を読み返さず、Design Docだけで各実装判断を行えるよう、必要な前提と契約を本文へ転記する。PoCとプロトタイプのdraft PRはURLで参照し、URLが無い場合は創作も省略もせず、その事実と原因、保全ブランチ等の代替の所在を記す。
13. 完成した Design Doc を指定文書へ実際に書き込み、書き込みは指定文書に限る。書き込む前に、送信する全文の控えを保存先ディレクトリと対象リポジトリの外に保存する。書き込みと同じ呼び出しで、再読取した全文が控えと完全一致し保持対象も不変であることをハッシュまたは機械的差分比較（`cmp` など）で確認し、確認だけのturnを作らない。
14. 書き込み操作を送信した事実、返却値が明示する結果、再読取で確認した保存内容を区別して報告する。

## 完了

文書作成は指定文書の保存と再読取確認で完了するが、設計が実装可能になるのは、実装を止める未解決判断がなく、必要な人間の設計承認が確認できた場合に限る。保存成功を設計承認または実装準備完了に読み替えず、自ら承認しない。

回答には、文書の保存先、文書化できた範囲、設計判断と根拠、採らない代替案、未解決判断（それぞれを決める判断主体、同定できなければ未同定）と実装への影響、不足する証拠、文書作成の完了可否、実装準備の可否、依頼のうち実施しなかった項目とその理由（それぞれを決める判断主体、同定できなければ未同定）、失敗、未検証事項、次に担うべき責務を返す。別skillを暗黙に起動しない。
