## 手順

1. プランの `## 申し送り (プロトタイプ → DD)` とプロトタイプを読む。実装は PR、なければプロトタイプ内で Git root を特定して branch diff と履歴を使う。Git 管理外なら履歴未確認を明記して利用可能な実装だけで続行する。PR が取得不能なら未確認を明記して申し送りだけで続行する。節がなければ実装から設計判断・根拠・スコープ外を再構成する。
2. `~/.claude/skills-config/create-design-doc/dd_template.md` を Read し、その見出し構成を
   骨組みにする (節の追加・削除・改番はしない)。未配置なら「テンプレートなしで作成」と宣言し、
   背景 / スコープ / 設計 / 設計判断と根拠 / Did not adopt / 未確定事項 の 6 節で書く。
3. DD を作成し、案件ディレクトリに `dd_<案件ディレクトリ名>.md` として保存する。設計判断は
   申し送りの根拠を転記し、採らなかった案は Did not adopt、スコープ外にしたことはスコープ外に
   残す。材料が無い項目は推測で埋めず、変更が発生しないなら「該当なし」、未決なら「未確定」と
   理由付きで書く。プロトタイプ側の欠落・矛盾も未確定に挙げる。再構成内容は DD だけに書き、プランは変更しない
4. DD に /dry-ssot-text → /purge-private-vocab を適用する。利用不能なら、重複説明の集約と source-plan 固有語の展開を直接検査した fallback と明記する。どちらも節構成・節番号・表・コードブロックを変えない
5. 保存してパスを報告し、DD レビューの LGTM を待って停止する。タスク分解・起票・本実装へ進まない
