- 結果を表す型は、呼び出し側がそれで何をするかで選ぶ: yesかnoかが値の全てで、下流の何もそれを導き直さないならboolean。呼び出し側が同じ値で型を絞り込むならtype predicate。不在または不正な状態がちょうど1つだけなら `T | null`。結果が3つ以上ある、結果ごとに持つデータが異なる、または1つの `null` や `undefined` が、呼び出し側が区別または復元する2つの意味を表しているならdiscriminated unionとし、呼び出し側が復元していたデータ (不明な識別子、失敗した入力) をそれを持つ分岐に載せる。全ての呼び出し側が同じに扱う2つの原因は1つの値のままにする。
- 組み合わせて読まれるbooleanやoptionalは、ありえない組み合わせを構築できないようdiscriminated unionに置き換える。異なる振る舞いを選択するboolean引数は名前付きのunion値または戻り値の型が異なる2つの関数に、同じ型の引数の間に置かれたbooleanは名前付きフィールドに置き換える。全ての呼び出し側を同じ変更で更新する。
- 「処理済み」の状態をコードが他の方法では判別できない値にbrandedまたはnominalな型を導入するのは、コンストラクタが1箇所にあり、かつ呼び出し側の重複適用または再確認が消える場合に限る。下流の何もその証明を消費しないbrandは型安全ではなく名前にすぎないので、追加しない。
- ドメイン関数を全域関数にする: 呼び出し側がそれに基づいて対処できるなら、`throw`、non-null assertion、cast、または「起こりえない」分岐を戻り値の型の中の値に置き換える。部分的な入力を受け取る境界は、引き続き最後に捕捉する場所とする。
