---
name: express-intent-in-code
description: コメント、boolean、nullableな戻り値に置かれた意図を、名前、直和型、全域関数、テストへ移す。コードで言えることを言い直すコメント、ありえない状態を許すbooleanやoptionalの組み合わせ、2つの意味を持つ1つのnull、振る舞いを選ぶboolean引数、I/Oに埋もれた判断を含むコードが渡されたときに使う。
---

- 渡されたコード中の全てのコメント、boolean、nullableな戻り値、boolean引数、インラインの判断を、その意図をコードで表す候補として扱い、それぞれを次の順で決める: コードがすでに同じことを言っているなら削除する。改名、結果型の選択、sum typeまたは名前付き定数の導入、関数の抽出、assertionまたはテストの追加によってコードへ移し、そのうえで削除する。コードが表せないこと、たとえば外部仕様、他所の不具合の回避策、明白な代替案を退けて選んだ意図的なトレードオフを述べている場合に限り残す。このコードを、整合を保たなければならない別の箇所に結び付けるコメントは、その結び付きが共有シンボルまたはテストになるまではそうした制約にあたるため、テストへ移すか残す。コメントを残す前に、それが記述する性質を述べる名前、またはその単位を述べる型エイリアスを試し、名前またはエイリアスがその全てを言い表せるならコメントを削除する。コード外の出典 (仕様の節、インシデント、契約条項、他システムの振る舞い) を引く既存コメントは、テストがその振る舞いを固定していてもその箇所に1行残す。テストが固定するのは何が起きるかであって、規則がどこから来たかではないためである。新しいテストは、削除したコメントの意図、または依頼が明らかにした制約を保持する。残したコメントはすでに理由を持っているので対になるテストを付けず、言語、ライブラリ、ランタイム、または型がすでに提供する保証はその提供元に任せる。残す判断は渡されたコードに既にあるコメントに適用し、依頼または編集が明らかにした制約は、後述のコメント追加に関する規則に従う。
- コメントが無い箇所でも、不明瞭な名前と責務に同じ順序を適用する: 意図をコードから読み取れるようにする最小の再構成と改名を実際に行い、名前や構造の提案で止めない。名前が明瞭であるとは、その語が指す対象を字義どおりに述べており、コードベースに初めて触れる読み手が、使用箇所や用語集を読む前に名前だけからその対象を分かることをいう。既存・追加を問わず全ての識別子とテスト名をこの基準に照らし、慣用句、比喩、業界やチームのjargonを字義どおりの語で言い直す。その際は各語を単独での通常の意味で判断し、識別子が保持または返すリテラル値が変えてはならない観測可能な出力であっても、識別子は改名する。すでに明瞭な名前は変えない。
- 編集は承認されたコードと対応する検証ファイルに限定する。編集してよいファイルを示す依頼はそのファイルを承認する。整理対象のコードを名指すだけの依頼は、変更する名前、型、シグネチャへのworking tree内の全参照も、exportされたものを含めて承認する: それらの呼び出し側、テスト、テスト名を同じ変更で更新する。
- 結果、状態、引数、または「処理済み」の値の型付けを変える前、あるいは `throw` を置き換える前に、[references/types.md](references/types.md) を読みその規則を適用する。
- I/Oを行う関数 (storeやリクエストをawaitする、時計や乱数源を読む) から判断を純粋関数または述語へ抽出するのは、その抽出が今存在するものを削除する場合に限る: 既存テストが必要とするfake、層、または注入された依存、同じ判断の2つ目のコピー、または関数内の時計や乱数の読み取り。既存テストが自明なstub越しにすでにその判断をカバーしている場合、新しい関数が得られるテストや、1行の条件に付けられる名前は数に入らない。何も削除されないなら、1行の述語であっても行をその場に残し、そうした条件を説明していたコメントは新しい関数ではなくテスト名またはassertionへ移し、消えなければならなかったものとともに候補を報告する。トランザクション内の再確認のように業務上の意味を持つI/Oの順序は呼び出し側のコードに残す。すでに純粋なコードの内部では、コメントが述べていた内容を名前が担うヘルパーは正当な移動であり、削除の条件を満たす必要はない。
- リポジトリの規則、ADR、またはそのリポジトリ固有の慣用がこれらの移動のいずれかと衝突する場合はリポジトリを優先する: その移動は適用せず、衝突を報告する。
- 整理の間にコメントを追加しない。依頼または編集が明らかにし、既存のどのコメントも述べていない制約も同様である: 理由を名前で述べるテスト、またはassertionで固定し、どちらでも保持できなければコメントに書かず報告する。
- 渡された入力、出力、外部から観測される振る舞いを保つ。機能やポリシーの変更は、コメントやTODOが求める変更も含めてこの整理の外に置き、承認されていない対象を必要とする再構成は適用しない。
- 編集後、設定済みのlintとtype checkを実行してリポジトリに無いものを報告し、特定した全ての境界ケースを含めて渡された振る舞い確認を実行し、観測した出力を変更前の根拠と比較する。
- lint suppressionは、新たに実行したlintの結果が不要と証明した場合に限り削除する。残るsuppressionには、コードがまだ表していない理由を1行残す。
- 確認したdiff、残した各コメントとコードがそれを表せない理由、適用しなかった各抽出またはbrandとその理由、lintと振る舞い確認の結果、範囲外の再構成、失敗または未検証の書き込み、未検証のまま残る振る舞いを報告する。
