まず次のコマンドをそのまま実行して、作業ディレクトリに fixture を用意してください。

```bash
mkdir -p docs docs/adr
cat > README.md <<'EOF'
# invoice-ingest

請求書を取り込み、仕訳の候補を作るライブラリ。

## 読者と公開範囲

この repository の文書 (`README.md`、`GLOSSARY.md`、`docs/`、`CHANGELOG.md`) は、導入担当者と社外の contributor が読む。`plans/` の設計書は社内の作業資料で、読者は開けない。

## 運用の要点

- 取り込んだ請求書は、審査を通ったものから仕訳の候補になる。
- 保留箱の見方は `docs/operations.md` にまとめている。
EOF
cat > GLOSSARY.md <<'EOF'
# 用語集

- **仕訳**: 取引を借方と貸方に分けて記録したもの。
- **取込**: 請求書の画像や PDF を読み取り、項目に分けること。
- **審査**: 取込の結果が、金額と取引先を読み取れているかを確かめること。
EOF
cat > docs/operations.md <<'EOF'
# 運用手順

## 毎朝の確認

1. 保留箱を開き、前日に入った請求書を確認する。
2. 判断できた請求書は、仕訳の候補に戻す。
3. 判断できない請求書は、保留箱に残す。
EOF
cat > CHANGELOG.md <<'EOF'
# 変更履歴

## 1.4.0

- 保留箱の一覧を、取込日で絞り込めるようにした。

## 1.3.0

- 保留箱に入れた理由を、請求書ごとに残すようにした。
EOF
cat > docs/adr/0003-manual-review.md <<'EOF'
# ADR-0003: 審査に失敗した請求書の扱い

- 状態: 採用
- 関連: issue #57

## 背景

請求書の取込では、金額や取引先を読み取れない請求書が出る。そうした請求書は審査に失敗したとみなし、仕訳を作らずに青箱ルートへ送る。

## 決定

- 審査に失敗した請求書は青箱ルートへ送り、手確が済むまで仕訳を作らない。
- 青箱ルートの入口は `routeToBlueBox()` で、`@invoice-ingest/review` の公開 API として出す。
- 手確の結果は審査の結果に上書きせず、別の列に残す。
- 判断のつかない請求書は保留箱に置く。保留箱の請求書は、仕訳の件数に数えない。
- 手確の待ち件数の上限は、Design Doc の T-16 で決めた値に従う。
- 月末は赤橋が止まるので、青箱ルートに送る件数を前もって見ておく。

## 結果

- 青箱ルートに送った請求書は、手確が済むまで仕訳の件数に数えない。
- 手確の担当者が増えても、保留箱の使い方は変わらない。
EOF
```

GLOSSARY.md に次の 2 語の項目を足して。

- 青箱ルート: 審査失敗時に手動確認へ送る経路
- 手確: 担当者による手動確認
