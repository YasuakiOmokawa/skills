## 目的

有効な受け入れ基準と ready の MECE Review を持つ既存の計画に、受け入れ基準ごとの検証の対応付けを `## Verification Plan` として書き、実装に備えさせる。

## 原理

- oracle による受け入れ判定: oracle は AC から導く。観測の起点 (Evidence anchors) には、リポジトリに実在すると確かめたファイル、関数、テスト、コマンドだけを書く。リポジトリ外の依存は anchor を創作せず Prerequisites に未解決として残す。
- 否定の主張には決定的な証跡を求める: 不在、件数の上限、並行性、経過時間、非影響に基づく oracle は、経路と観測境界が完了した肯定的証跡と、決定的な失敗シグナルまたは制御された seam を Required effects が名指ししたときだけ、対応付けを完了とする。固定時間の待機だけなら、足りない証跡を Prerequisites に未解決として残す。列挙した書き込み経路で確かめる不変条件は、関係するいずれかの状態の書き手が列挙の外に現れたら決定的に落ちる tripwire を Required effects が名指ししたときだけ完了とする。経路ごとの確認だけなら、tripwire の不足を Prerequisites に未解決として残す。

## 契約

入力: `## Acceptance Criteria` の AC と `- Gate: ready` の `## MECE Review` を持つ計画。どちらかが揃わなければ、準備せず、Verification Plan も作らず、足りない条件を報告して止まる。未確認の判断条件は、中身を創作せず、Gate を `ready` にするための不足条件として示す。

出力: 計画に唯一の `## Verification Plan` 節。既存があれば内容全体を置き換える。節は `- AC IDs: <現在の AC-ID を昇順で ", " 連結>` 行と、AC ごとに 1 つの `### AC-NNN` エントリだけから成り、各エントリは空でない `- Oracle:`、`- Evidence anchors:`、`- Prerequisites:`、`- Required effects:` を 1 行ずつ持つ。検証の意図はこの節にだけ置き、別の検証文書を作らない。前提が未解決でも、Required effects には oracle の観測に要る最小限の具体的な操作や状態変化を書く。これは後で要る承認の記述であって、承認を与えるものではない。

## 禁止

- 依頼が許可した計画以外への書き込み。製品コードと外部状態の変更。
- 保存できないときの別の保存先への迂回。書けなかったことを報告して内容を回答で返す。
- 未解決の前提を推測で埋めること。

## 完了条件

全 AC が Verification Plan に対応付けられ、その内容と書き込みの結果を返した。再読取などで確かめていない書き込みを成功と報告しない。対応が未完の AC や未解決の前提条件があれば、部分的な完了として報告する。
