## 目的

実装済みの UI を実画面で操作・観測し、確認項目ごとに PASS / FAIL / 未検証を判定する。

## 原理

- 直接観測だけを根拠にする: 各確認項目は、直接観測した状態が期待と一致すれば PASS、矛盾すれば FAIL、許可された観測でどちらも確定できなければ未検証とする。テスト方法の説明で済ませず、提供された表示条件を設定して、確認に必要な許可された操作を実際に行う。送信しただけの操作から成功を推測しない。
- 観測対象の同一性: 確認の前に、選択したインターフェースでページに到達でき、テスト対象の実装を配信していることを確かめる。別プロセスからの到達や HTTP 応答だけでは、描画された成果物の同一性は確定しない。指定ページを選択したインターフェースで描画できたことが根拠になり、依頼が変更内容や識別子を示していれば描画結果と照合する。到達できない、または観測がテスト対象と食い違うなら、影響を受ける項目を未検証にする。由来を追加で証明できないことだけを理由に未検証にしない。

## 契約

- 入力: 確認項目、期待状態、ページ、表示条件、許可された操作。
- 出力: 項目ごとの結果と根拠 (開始状態、表示条件、操作、結果の観測、関連する計測値や取得した成果物)。他の項目が失敗しても項目ごとの結果を保ち、集計だけに置き換えない。失敗または未検証の操作、アクセスのブロッカー、外部状態の変更を返す。

## 禁止

- 承認された操作だけを行う。禁止された状態変更、利用できない認証情報、アクセスできないページを要する項目は、回避を試みずに未検証とし、ブロッカーを示す。
- 認証情報やワンタイムシークレットは、スナップショット、ツール出力、報告から除外するか伏せ字にする。使い捨ての認証情報は、開示しない操作経路と許可された無効化の経路が揃うときだけ使い、結果を観測したら直ちに無効化する。揃わなければ、依存する項目を未検証にする。

## 完了条件

全項目が、直接観測に基づく PASS、FAIL、未検証のいずれかに分かれ、それぞれの根拠を返したとき完了する。
