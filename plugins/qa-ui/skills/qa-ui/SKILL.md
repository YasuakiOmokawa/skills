## 手順

1. 提供された表示条件を設定し、提供されたページ上で、確認項目の確定に必要な許可された操作だけを、テスト方法の説明で済ませず実際に行う。
2. 確認を実行する前に、選択したインターフェースを通じて、ページに到達でき、テスト対象の実装を配信していることを確定する。別プロセスからの到達は、選択したインターフェースからの到達を確定せず、HTTP 応答だけでは、描画された成果物の同一性を確定しない。依頼が指定したページを選択したインターフェースで描画できたことが、テスト対象の実装である根拠になる。依頼が変更内容や期待する識別子を示していれば、描画結果と照合する。到達できない場合、または描画結果、識別子、別経路の観測がテスト対象の実装と食い違う場合は、影響を受ける確認項目を未検証のままにする。由来を追加で証明できないことだけを理由に未検証にしない。
3. 各確認項目は、送信しただけの操作から成功を推測せず、直接観測した状態が期待と一致する場合だけ PASS、期待と矛盾する場合は FAIL、許可された観測でどちらの結果も確定できない場合は未検証とする。根拠として、開始状態、表示条件、操作、結果の観測、関連する計測値や取得した成果物を記録する。
4. UI またはその根拠に認証情報やワンタイムシークレットが含まれる場合は、スナップショット、ツール出力、報告から除外するか伏せ字にする。使い捨ての認証情報は、開示しない操作経路と許可された無効化の経路が揃うときだけ使い、結果を観測したら直ちに無効化する。どちらかが無ければ、認証情報に依存する確認項目を未検証のままにする。
5. 他の項目が失敗しても項目ごとの結果を保ち、集計した状態だけに置き換えない。
6. 承認された操作だけを行う。禁止された状態変更、利用できない認証情報、またはアクセスできないページを必要とする確認項目は未検証のままにし、回避を試みずにブロッカーを示す。
7. リポジトリに確立済みの起動・ログイン手順があればそれを使い、探し直さない。

## 完了

全項目の観測した結果と根拠、失敗または未検証の操作、アクセスのブロッカー、外部状態の変更を報告する。
