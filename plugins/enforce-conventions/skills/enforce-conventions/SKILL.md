## 目的

書き手の注意や弱い仕組みに頼っている規約を、破ると最も早く落ちる仕組みへ移す。

## 原理

- 規約は覆える最も強い場所に置く: 強制力は違反が落ちる時点で決まり、強い順に、違反を書く場所が無い構造と型検査、lint、テスト。実行して初めて例外になる構造 (private、必須引数) と実行時の検査はテストと同じ強さに数える。規約ごとに強い場所から試し、覆える部分をそこに置いて、残りを次の場所で試す。どこでも覆えない規約は、述べられた規約なら文書に残し、観測した規約なら報告する。
- 違反が落ちるのを見るまでは担保ではない: 仕組みを置くたびに、規約を破る最小の例でその仕組みが落ちることと、今のコードが通ることを実行して確かめる。落ちるのを見ていない仕組みは未検証として報告する。

## 契約

- 入力: 実装差分。述べられた規約と観測した規約を集める。どちらにも当たらない約束は直さず、候補として報告する。覆える最も強い場所に既に在る規約と、製品が何を出力するかの固定は対象にしない。
- 述べられた規約は、文書、コメント、テスト、実行時の検査、lint の rule が述べる、コードの書き方への約束のうち、差分の行が守るか破るもの。破る箇所は違反である。
- 観測した規約は、述べられていないが作業ツリーの全箇所が満たし、利用する側が当てにしている約束のうち、満たす箇所か外れる箇所が差分にあるもの。述べられていない約束を規約として扱う前に [observed-conventions.md](references/observed-conventions.md) を読む。
- 型に置くとは、破るコードを書けないか型検査で落ちる状態にすることで、手段は問わない。repo に同じ種類の約束を守る書き方があれば合わせ、無ければ足すコードが最も少ない手段を、言語と repo の慣用で書く。
- 対象を名指す依頼は、仕組みを置くファイル (型定義、設定済みの lint の設定、テスト) の変更と、型やシグネチャを変えて直す作業ツリー内の全参照を承認する。
- 保護するパスは、依頼が変えないと名指したファイルと、`Define-Done-Seal:` か `Define-Done-Supersedes:` の trailer を持つ commit のファイルである。これを変えずに type check、lint、テストが通らない変更は戻し、次の場所で試して、置けなかった理由としてそのファイルと行を報告する。
- lint は、repo に設定済みの linter の組み込み rule、次にその linter の独自 rule で書く。
- 差分の中の違反は、振る舞いを保てる範囲で直し、保てなければ直さず報告する。差分の外の違反は、型なら同じ変更で全参照を直し、lint とテストなら rule の対象 path を違反の無い範囲に絞って、覆わない範囲と違反の箇所を報告する。
- type check、lint、テストは変更の前と後に流し、新しく落ちた箇所を残さない。前から落ちている検査は違反が落ちた根拠にしない。
- 仕組みへ移した約束を述べていたコメントは削除する。
- 移した先で違反の例が落ちるのを見たときだけ、それまで規約を落としていた実行時の検査、テスト、型が到達できなくした分岐を外す。外部入力を読む境界の検査は残す。
- 規約が見つからなければ何も変えず、対象なしと報告する。
- 出力: 規約ごとの出典、今まで落としていた場所、置いた場所、強い場所に置けなかった理由、違反が落ちた観測、適用範囲、直した参照の数。観測した規約の判断に読んだ全箇所の `path:line`。文書に残すか置かずに報告した規約の理由。文書から外せる記述。外したもの。見送った候補。

## 禁止

- commit、push、PR作成、外部状態の変更をしない。
- 観測で決まらない約束を固定しない。
- 文書が述べる規約は述べたとおりに置き、厳しくも広くもしない。
- 読みが分かれる規約は移さず報告する。
- 文書と、保護するパスを変えない。
- 仕組みを通すために、抑止の directive、警告への格下げ、ignore を足さない。
- 新しい依存を足さない。要るなら候補として報告する。
- 型が受け入れる値に対する振る舞いを変えない。
- 値の形を変えない。
- 今ある値を新しく弾く検査を足さない。

## 完了条件

集めた規約のすべてが、移した、一部を移した、文書に残した、置かずに報告した、のいずれかに分かれ、見送った候補と、設定済みの type check、lint、テストを変更の前と後に流した結果を報告したとき完了する。
