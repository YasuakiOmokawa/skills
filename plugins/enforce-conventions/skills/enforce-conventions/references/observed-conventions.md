# 観測した規約

- 観測で決まらない約束: 名前からの推測、今たまたま無いことからの推測、多数決で約束を固定しない。
- 全箇所: 値を組み立てる箇所、関数を呼ぶ箇所、値の取りうる範囲で分岐する箇所を指し、テストの中の箇所も数える。観測は作業ツリー全体で行い、満たす箇所が 1 箇所でもよい。
- 当てにしている: 約束を破る値が来ると、例外になるか、破れた場合を名指して扱わずに結果を出す利用箇所があること。破れた場合を名指して扱う (そのための枝か代わりの値がある) 利用箇所しか無ければ当てにしていない。条件を順に調べて先に当たった結果を返すだけの分岐は、破れた場合を名指して扱っているとは数えない。
- 満たさない箇所: 1 つでもあれば規約ではない。外れた箇所を直さず、その箇所と、そこを直せば守れる範囲を報告する。コードが今許している呼び出しを禁じない。
- 差分の箇所だけが破るとき: 既存の全箇所が満たす約束を差分の箇所だけが破っているときも直さず、他の候補と分けて報告する。
- 外から来る値: 作業ツリーを読んでも取りうる値が分からない値。読み込んだ値 (JSON、HTTP の応答、DB の行、ファイル、環境変数、CLI の引数)、製品コードで型を主張しただけの値 (cast、`any` からの代入)、公開する package の入口の export が受け取る値を指す。利用する側が当てにしていても、その型は絞らない。
- テストの中の cast: 外から来る値とせず、書かれた値そのものを組み立てた値として観測する。
- 外へ出す前の書き換え: 関数の中で作って外へ出す前に書き換える値は、外へ出る時点の値で観測し、1 つの組み立てに書き直してよい。外から受け取った値への代入は書き直さず報告する。
- 値の取りうる範囲: 絞るのは、コードがその値をリテラルと比べて分岐しているときだけ。全箇所が同じ値を渡しているだけでは絞らない。
- 取りうる値をすべて扱う分岐: 値の取りうる範囲で分岐し、既定の枝に落ちる値が 0 個か 1 個の分岐は、取りうる値をすべて扱うという観測した規約である。この規約は、取りうる値を足すと型エラーになる形にして置く。repo にその形の既存の helper があれば使い、無ければ例外を投げるコードを足さずに、型検査だけで落ちる書き方にする。既定の枝が 2 個以上の値をまとめて受ける分岐は変えない。
- 既にある条件: 今ある値を新しく弾かずに、既にある条件に名前と型を与えるのは足してよい。
- 呼ぶ箇所が無い関数: 引数の型を絞らない。
- 読み切れないとき: 全箇所を読み切れない約束は絞らず報告する。直す参照の数に上限は無い。
- 絞らなかった理由: 外から来る、当てにしていない、読み切れない、のどれかで報告する。
- 置き場所: 型検査、lint、テストにだけ置き、実行時に例外を投げる構造には置かない。述べられた規約のうち既に実行時の検査が弾いているものは、実行時に例外を投げる構造へ移してよい。
- 型を置ける言語: 型注釈を compiler や editor が既定で検査する言語なら、型検査のコマンドが repo に無くても型を置ける場所に数える。型注釈を別の道具が検査する言語では、repo にその検査の設定があるときだけ数える。
- 状態の遷移: 遷移する関数の引数の型に置くまでとし、遷移の一覧を持つデータは作らない。
- 値を書き換えないことの約束: 対象にしない。
- 値の形: 実行時の値が持つ field の有無と、値の種類 (plain object、class の instance、primitive)。
