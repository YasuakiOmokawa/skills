## 手順

1. 依頼から、要求、既存スキーマ、SQL、指定された成果物を特定し、既存スキーマとSQLを実際に読み取って要求と照合する。読取を試みても観測できない資料だけを未検証とし、要求だけから作った暫定モデルを完了扱いにしない。
2. 確定している関係と制約を全てモデル化し、1列に1つの意味を持たせ、参照整合と制約はDBに宣言する形にする。確定できない多重度と、根拠のない物理型や制約は、慣例で補わず、未解決事項として分けるか、DBML上も未確定値として表す。DBMLが有用なら、確認できた内容を一貫して表す。
3. SQLから確認できる構造上の問題を該当箇所へ結び付け、整合性、参照、検索、更新への影響を示す。
4. 書き込みを指定されたモデル成果物に限定する。本番データベースへ接続せず、DDLを実行せず、実データを変更しない。

## 完了

エンティティ、属性、関係、制約、必要なDBML、根拠付きのSQLアンチパターン、仮定、未解決事項、未検証事項、書けなかった成果物を返す。
