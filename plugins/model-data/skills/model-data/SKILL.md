## 目的

業務要求と既存のスキーマや SQL から、一貫した一つのデータモデルを作る。

## 原理

- 制約は DB で宣言する: 確定している関係と制約を全てモデル化し、1 列に 1 つの意味を持たせ、参照整合と制約は DB に宣言する形にする。既存のスキーマがこの原理に反する箇所 (複数の値を詰めた列、宣言されていない必須の外部キー、複数の意味を持つ列) は、モデルとの差として該当する列に結び付けて示す。
- 確定したものだけをモデルにする: 確定できない多重度と、根拠のない物理型や制約は、慣例で補わず、未解決事項として分けるか、DBML 上も未確定値として表す。

## 契約

- 入力: 要求、既存スキーマ、SQL、指定された成果物。既存スキーマと SQL は実際に読み取って要求と照合し、読取を試みても観測できない資料だけを未検証とする。要求だけから作った暫定モデルを完了扱いにしない。
- 出力: エンティティ、属性、関係、制約、必要な DBML (確認できた内容を一貫して表す)、既存スキーマとの差とその根拠、仮定、未解決事項、未検証事項、書けなかった成果物を返す。

## 禁止

- 書き込みは指定されたモデル成果物に限る。
- 本番データベースへ接続せず、DDL を実行せず、実データを変更しない。

## 完了条件

既存のスキーマと SQL を読んで照合したモデルと、未解決事項・未検証事項の区別を返したとき完了する。確かめていない書き込みは成功として報告しない。
